# Exdox website

## Private accounting pilot (2026-10-03)

- VAT review (2026-10-03): new Accounting VAT review tab selects a period, shows draft boxes 1–9 and transaction-level details, flags unclassified older/manual entries, accepts reviewed journal-linked classifications, exports an evidence CSV, and closes a reviewed UK standard invoice-basis period. Invoice/bill lines now choose a VAT code and issue/tax dates; explicit Exdox posting selects its VAT code and date. Credit notes and reversals flow through the report. It does not file with HMRC or certify MTD compatibility, and special schemes/reverse charge/import VAT/partial exemption need separate work. The server VAT routes must deploy first; the owner checks the live site and workflow. Never delete or move mobile signing keystores or details.
- Dashboard navigation now shows Accounting for every signed-in user. It is locked unless the active account email is `terryreedbfv@outlook.com`. The corresponding API independently verifies the current user record and email; the browser lock is only a visual cue.
- `src/AccountingPage.tsx` is a separate workspace for chart of accounts, balanced GBP journals, a posted journal export, trial balance, profit and loss, and balance sheet. It does not alter the existing Costs, Sales, Xero, billing, or Android flows. API deployment must precede the website update.
- The Accounting workspace now has a separate Invoices & bills screen. It posts itemised GBP invoices and bills to the ledger, shows outstanding amounts, accepts partial/full payments, and prints sales invoices with user-entered business/customer details. It does not send invoices or alter the existing Sales and Costs workspaces.
- Bank reconciliation (2026-10-03): the Accounting tab has a Bank reconciliation screen. It reads a local GBP CSV with Date, Description, and signed Amount columns (or Debit/Credit), requires opening/closing balances, imports at most 500 lines, and matches each line to an exact signed movement posted to the Accounting Bank account. It shows unmatched lines and the difference between statement closing and ledger Bank balance. Missing ledger transactions must first be posted through Accounting Journal or payments. This does not use the existing Exdox bank integration, does not connect a live bank feed, and does not post imported statement lines to the ledger.
- Corrections & locks now supports period closing, dated reversals, and quantity-based credit notes for posted invoices and bills. Outstanding balances exclude reversed payments and active credits; voided documents remain visible in history. Post Exdox records lists recent reviewed GBP Costs and Sales, requires an explicit duplicate check, and creates one Accounting snapshot without changing the source record. Later source edits are flagged. The server must deploy before this UI.
- This is a private double-entry foundation, not feature parity with Xero. Bank feeds, VAT returns, payroll, invoice email sending, and a refund workflow remain absent. Do not represent it as a full accounting replacement until those workflows are implemented and verified.
- Never delete or move a mobile signing keystore or signing details. The owner checks the live website and deployment workflow after source pushes.

This repository contains the public Exdox website and the signed-in React/TypeScript workspace. The live site is `https://exdox.co.uk`; source is `https://github.com/pz22pzpzai/exdox`.

## Main files

- `src/App.tsx`: public pages and authenticated workspace UI.
- `src/styles.css`: site styling and self-hosted font declarations.
- `src/googleAnalytics.tsx`: consent-dependent public analytics.
- `public/branding/`, `public/videos/`, `public/fonts/`: static media and fonts.
- `public/.htaccess`: Apache security, cache, and SPA rewrite rules.
- `.github/workflows/deploy.yml`: GitHub Actions Vite build and FTP deployment.

## Build and deployment

- `npm install`, `npm run dev`, and `npm run build` are the local commands. The build runs TypeScript and Vite and writes `dist/`.
- Pushing `main` triggers the GitHub Actions build and FTP upload using repository secrets. Never record secret values here.
- Do not inspect the live website or deployment workflow after a push; the project owner does those checks.
- Preserve unrelated working-tree edits. Do not commit build output, local machine settings, or temporary packages.
